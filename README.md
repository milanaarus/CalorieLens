# CalorieVision / CalorieLens

Учебный проект: оценка калорий по фотографии, личный дневник и недельная статистика. Главная страница содержит интерактивную 3D-тарелку.

## Актуальная версия

Текущие исходники находятся в `CalorieVision-source.zip`. Архив содержит читаемые исходные файлы React и FastAPI, инструкции и тесты. Распакуйте папку `CalorieVision` для локальной разработки. Dockerfile извлекает тот же архив и собирает приложение из него.

Папки `frontend` и `backend`, оставшиеся от первоначального коммита, сохранены как история начального каркаса; Docker-сборка их не использует.

SHA-256 пакета: `0ebdbbbfde754d3d6f2ba271bd2e0e681ea76de730eb1ee541dde031d97ccb54`.

## Размещение на Render

В `render.yaml` указан бесплатный пробный Web Service и бесплатная PostgreSQL в одном регионе. Оплата не требуется для указанных тарифов, но учитывайте текущие ограничения Render: база бесплатного тарифа имеет срок действия, а памяти Web Service может не хватить для PyTorch. Работу распознавания нужно проверить после сборки. Переход на платные ресурсы — отдельное решение владельца.

Секрет авторизации генерируется Render. Личные базы, пароли и `.env` в архив не включены. После запуска проверьте регистрацию, анализ фотографии, запись в дневник и прямое открытие `/login`.

## Бесплатная базовая версия

33 продукта с проверенными КБЖУ USDA доступны без внешних пищевых API. Расчёт нескольких компонентов тарелки, дневник и недельная статистика. Онлайн-поиск опционален. Облачное распознавание отключено. 245 названий расширенного каталога не означают 245 категорий распознавания. Инструкция: BASIC-VERSION.md внутри исходников.






## Онлайн-поиск КБЖУ

Подключён Open Food Facts Search-a-licious: выбор товара, источник, кэш. USDA API требует отдельный ключ. Подробности: ONLINE-NUTRITION.md в архиве.

## Адаптивный интерфейс

Навигация и формы адаптированы для телефона, планшета и компьютера. Проверены ширины 320, 390, 768, 1024 и 1440 px. Сохранена 3D-тарелка.

## Последние изменения: порции, приготовление и черновики

- Для указанных приготовленных гарниров и мясных продуктов предлагается 150 г. Массу проверяет пользователь; вес по фото не измеряется.
- Смена приготовления очищает прежние КБЖУ. Источники и ручное исправление сохранены.
- Черновик хранит состав и массу в текущем браузере, без фотографии, и очищается при выходе.
- Если продукты на фото не найдены, доступны повторная загрузка и ручной ввод с переносом фото и типа приёма пищи.
- Устранено промежуточное округление расчётов. Проверены 25 серверных и 7 клиентских тестов, сборка frontend.
- Модель YOLOv8n и набор её классов не изменялись.

По просьбе владельца каждое завершённое и проверенное изменение фиксируется коммитом и публикуется на GitHub. Публикация на Render проверяется отдельно.

## Обновление распознавания

Восстановлена исходная YOLOv8n (COCO), порог 0,30. Файл yolov8n.onnx используется Docker-сборкой; для локального запуска скопируйте его в backend/models/. Платные API и PyTorch на сервере не нужны. Массу подтверждает пользователь.

## Выбор приготовления при поиске

Общие запросы «рис», «курица», «гречка» и другие явно сопоставленные продукты предлагают только существующие записи встроенного справочника. Пользователь выбирает запись до подстановки КБЖУ. При замене сохраняется масса. Недоступные способы приготовления не выдумываются. Проверено 26 серверных и 7 клиентских тестов.
